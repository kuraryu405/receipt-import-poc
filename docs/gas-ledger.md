# 小口出納のGAS試作

実際の台帳の運用がまだ分からないので、架空の月別台帳を作った。まずは読み取り結果を人が確認して、1枚分を1行として登録するところを試す。

[架空台帳を開く](https://docs.google.com/spreadsheets/d/1IZ4Q6p-0NGgo-jhbtUueduCIJEpOw2yr9MiONWdzcEk/edit)

台帳は「2026-10」「2026-11」「設定」の3タブ。費目や月の区切り、開始残高は試作用の仮定で、社内の運用を再現したものではない。

## 使い方

1. 台帳を開き、「小口出納」→「レシートを登録」を選ぶ。メニューが出なければページを再読み込みする。
2. PoCの「応答のJSONを表示する」の内容を貼り付け、「JSONを取り込む」を押す。Geminiを呼ばずに試すなら「架空データを入れる」を使う。
3. 元画像を別画面で見ながら、取引日・支払先・摘要・出金額・消費税・支払方法・登録番号を直し、費目を選ぶ。
4. 確認欄にチェックを入れて「確認して登録」を押す。取引日の月のタブに1行追加される。

現在はJSONを手動で渡す。Next.jsの解析画面から直接GASを呼ぶ接続と、GASからの画像解析はまだ実装していない。GASにGeminiのAPIキーは置いていない。

複数枚の応答 `{ receipts: [...] }` は最大10枚まで取り込める。1枚ずつ選んで確認・登録する。切り替えると未登録の編集内容は消えるので、登録してから次のレシートに進む。

公開データセットのレシートは試作台帳の月と一致しない場合がある。確認用に日付を変更する場合は架空の取引として扱い、OCR精度の計測結果に混ぜない。元の取引日で使うには、その月の台帳と繰越式を別途用意する必要がある。

## 台帳のルール

- 1枚につき1行。商品明細は品名をまとめて摘要にする。税率別の仕訳には対応していない。
- 小口現金の出金だけを登録する。現金以外の支払いは拒否する。補充の入金は台帳で別途入力する。
- 金額は整数の円。出金額は1〜10,000,000円、消費税は空欄または出金額以下。
- 開始残高は「設定」B4の50,000円。10月の月末残高を11月の期首残高に引き継ぐ。
- 行の残高は登録順で計算する。取引日順には並べ替えない。後から10月を直すと11月の残高にも反映される。月締めの制御はない。
- 月別タブの5行目が見出し、6〜505行目が登録領域。列構成が違う場合は登録を止める。

登録IDはJSON取り込み時に生成し、同じ確認画面からの再送には同じIDを使う。同じID・同じ内容なら行を追加せず、同じIDで内容が変わった場合はエラーにする。書き込み中はDocumentLockで同時登録を排他する。

**JSONを取り込み直したり画面を開き直したりすると新しい登録IDになる。画像の再アップロードを含む重複判定は行っていない。** PoCの `imageId` は画面を開き直すと再利用されるため、台帳の登録IDには使わない。

## GASを引き継ぐ

ソースは `gas/Code.gs`、`gas/ReceiptDialog.html`、`gas/appsscript.json`。台帳に紐づくスクリプトなので、Google Sheetsの「拡張機能」→「Apps Script」で編集できる。今回の台帳には組み込み済み。

別の台帳に移す場合は、この試作台帳をコピーして列構成と数式を引き継ぐ。スクリプトがコピーされているか確認し、なければ3ファイルを貼り付ける。Apps ScriptのHTMLファイル名は `ReceiptDialog`。マニフェストはプロジェクト設定で表示できる。

`onOpen` がメニューを作り、`showReceiptDialog` が確認画面を開く。`registerApprovedReceipt` が入力を検証し、月別タブに登録する。追加のトリガー設定やWebアプリのデプロイは不要。

権限は現在のスプレッドシートとダイアログ表示に限定している。Drive全体のアクセスや外部通信は使っていない。初回実行時のGoogle認可は利用者ごとに必要になる場合がある。台帳は作成時点では非公開。

## 実運用につなぐ前に確認すること

実際の台帳の列、月の区切り、費目、補充・立替・現金以外の扱い、承認者を確認する。次は解析画面で確認したデータを直接渡す接続と、画像から登録まで引き継げる永続IDを作る。画像の保管先と月締め・修正履歴も、その運用に合わせて決める。

GASを台帳に紐づける構成と権限の説明は、Google公式の [コンテナバインドスクリプト](https://developers.google.com/apps-script/guides/bound) と [認可](https://developers.google.com/apps-script/guides/services/authorization) を参照した。

## 2026-10-06の動作確認

Google SheetsとApps Scriptの実画面で操作し、台帳のセルも読み返した。Geminiは呼んでいない。以下はすべて架空データによるGASの確認で、OCRの実測ではない。

| 操作 | 結果 |
| --- | --- |
| 台帳を再読み込みし、メニューから登録画面を開く | 「小口出納」→「レシートを登録」で起動 |
| 10月6日の1,234円を確認して登録 | 10月8行目に追加。10月末残高66,566円、11月期首も66,566円 |
| 2枚のJSONを取り込み、11月6日の500円を登録 | 11月6行目に追加。11月末残高66,066円。消費税の空欄も保持 |
| 登録ボタンを同じ内容で再度押す | 「登録済み」と表示。行は増えない |
| 登録済みの500円を501円に変更して再送 | 同じ登録IDで内容が違うため拒否 |
| 支払方法をクレジットカードに変更 | 現金払いではないため拒否 |
| 不正なJSONを取り込む | 日本語のエラーを表示 |
| 12月のレシートを選択し、必須項目と確認欄を埋める | 対応する月のタブがないため登録ボタンが無効 |

同時登録の競合、500行の上限、別のGoogleアカウントでの認可、実際の社内台帳への接続は未確認。
